# 设计台 功能全景 · 业务流程 · 界面信息架构（v1.2 需求动线版）

> 背景：v1.1 把面板做成了 Figma 级编辑器，但用户打开面板后第一反应是「**我在哪里发需求？**」——这是信息架构问题，不是功能缺失。本文把「谁在哪里做什么」一次性梳理清楚，并作为 v1.2「需求动线」改造的验收依据。
> 核心结论：**对话是需求入口，面板是设计工作台**。面板必须把这一点做成显式动线：面板内可以直接写需求 → 一键带回对话；并在顶栏常驻「回到对话」。

---

## 一、两种表面，两种职责

| 表面 | 位置 | 职责 | 不该做的事 |
|---|---|---|---|
| **对话（Conversation）** | DSH 主区域 | 用户用自然语言提需求/改需求；agent 调 `design_start/check/export` 等工具；澄清问题与汇报 | 不适合精确改样式、逐像素调参 |
| **设计台面板（Panel）** | 侧边栏「设计台」→ 主区域全局面板 | 看/选三档变体、画布直接改、图层树、内联评论、Tweaks、质检报告、设计系统、版本、导出 | 不该让用户「找输入框」——它必须把需求交回对话 |

**动线原则**：任何需要在对话里说的话，面板都提供一个「写下来 → 复制 → 切回对话」的按钮；任何可以在面板里做的事，都不要求回对话。

## 二、入口（用户从哪进来）

1. **对话直接说**（主入口）："用设计台做一个××落地页，三档方向" → agent `design_start` → 用户点侧边栏「设计台」查看/继续。
2. **侧边栏「设计台」**：打开面板 → 项目库（总览）。总览第一屏就是需求输入区。
3. **插件/技能提及**：系统提示已注入设计台工作流，agent 会自动按 `design_start → design_context → 写变体 → design_check → design_export` 执行。

## 三、功能全景（谁拥有什么）

### 3.1 Agent 工具（10 个，对话侧）

| 工具 | 作用 | 面板对应入口 |
|---|---|---|
| `design_start` | 建项目 + brief + 种子变体 | 总览「新建设计」/ 需求输入 |
| `design_context` | URL/repo/图片/文字导入语境 | 左栏「语境」tab |
| `design_system` | 读写设计系统 tokens/DESIGN.md | 右栏「设计系统」tab |
| `design_scaffold` | 取/写 10 种起始脚手架 | 新建时的类型选择 |
| `design_check` | 真实浏览器质检 + 评分 + 修复清单 | 顶栏「检查」/ 右栏「检查」tab |
| `design_tweak` | 读写 TWEAK 块 | 右栏「Tweaks」tab |
| `design_comments` | 读取/解决内联评论 | 左栏「评论」/右栏「评论」 |
| `design_export` | html/zip/pdf/png/pptx | 顶栏「导出」/ 右栏「导出」 |
| `design_projects` | 列表/详情/删除/版本 | 总览项目库 / 右栏「版本」 |
| `design_serve` | 同源预览 URL | 顶栏「打开预览」 |

### 3.2 面板区域（7 个）

| 区域 | 内容 | 主要动作 |
|---|---|---|
| TopBar | 返回、项目名、状态、分数、画布/画板、检查、导出、更多、语言、帮助、**回到对话** | 导航与全局动作 |
| ToolBar | 选择/评论、检查器/左栏、视口/设备/旋转、缩放、标尺/网格/参考线、撤销/重做/保存 | 画布工具 |
| LeftRail | **需求**、变体、图层、语境、评论 | 结构浏览与需求提交 |
| Canvas | 设备框/标尺/参考线/画板视图/评论钉/浮动工具条/拖拽缩放 | 直接编辑 |
| Inspector | 属性（8 组）、Tweaks、评论、检查、导出、设计系统、版本 | 精细调整与报告 |
| StatusBar | 选择路径、尺寸、缩放、保存、桥、分数、提示 | 状态反馈 |
| FlowStepper | 需求 → 语境 → 变体 → 迭代 → 质检 → 导出 | 告诉用户「下一步做什么」 |

## 四、业务流程（端到端）

### 4.1 主流程：从一句需求到可交付设计

```
① 提需求（对话 或 面板需求输入 → 复制回对话）
   ↓ design_start：项目 + brief + DESIGN.md + 种子变体
② 补语境（可选但推荐）design_context：URL 计算样式 / repo tokens / 图片取色 / 文字备注
   ↓ 设计系统可 adoptSystem
③ 三档变体：agent 写 design/a.html(规范) b.html(进阶) c.html(前卫)
   ↓ 面板：变体轨切换 / 画板视图并排
④ 迭代（三通道）
   - 对话：结构性修改（"加一屏""换布局"）
   - 内联评论：组件级修改（点画布元素留言 → design_comments）
   - 画布直接编辑：样式/文字/拖拽/缩放/对齐，保存即写回文件
   - Tweaks：颜色/字号/圆角/密度实时调参
   ↓
⑤ 质检 design_check：0–100 + A–F + 分类问题 + 可点击选择器 + 截图
   ↓ 修复清单 → 回④，直到 ≥90
⑥ 导出 design_export：HTML / ZIP / PDF / PNG / PPTX（deck 每屏一页）
   ↓
⑦ 版本与交接：版本快照可回滚；ZIP 含 design/ + system/ + 项目摘要
```

### 4.2 迭代循环（面板内的三条通道怎么选）

| 想改什么 | 用什么 | 面板动作 |
|---|---|---|
| 整体结构/新增区块/换方向 | 对话 | 左栏「需求」写下 → 「复制给 Claude 并去对话」 |
| 某个按钮/间距/颜色 | 画布直接编辑 | 选择元素 → 浮动工具条/属性面板；或 <kbd>⌘S</kbd> 保存 |
| 组件级反馈、让人看 | 内联评论 | 评论模式点元素留言 → agent 读 `design_comments` |
| 全局视觉参数（色/字/圆角） | Tweaks | 右栏 Tweaks 实时调 |
| 全站排印/系统一致性 | 设计系统 | 右栏设计系统编辑 tokens → 重新检查 |

### 4.3 质检修复流程

`检查` → 分数环/等级 → 分类条 → 问题清单（critical→low，带选择器与 fix 文案）→ 点选择器在画布选中 → 改 → `重新检查`。面板提供「**让 Claude 修复这些问题**」：把当前轮 issues 生成结构化指令 → 复制 + 切回对话。

### 4.4 设计系统导入流程

右栏「设计系统」→ 导入 URL（抓真实计算样式）/ 本地路径（扫 CSS/Tailwind/tokens）/ 手工 JSON → 保存 → 质检 system 类目按 token 比对 → 分数提升。可下载/复制 tokens。

### 4.5 导出与交接

右栏「导出」或顶栏「导出」→ 选格式 → 结果路径 + 下载链接 → 历史记录。PPTX 对 deck 一屏一页；PDF 按打印 CSS；ZIP 可交接给工程。

### 4.6 版本回滚

右栏「版本」→ 保存带标签快照 → 列表 → 恢复（确认）→ 变体回到快照；面板保存会自动存历史。

## 五、界面信息架构（每屏该有什么）

### 5.1 总览（项目库）

1. **需求输入卡（第一屏第一焦点）**：类型 chips（落地页/仪表盘/移动端/幻灯片/海报/一页文档）+ 需求文本域（goal/受众/约束合一，或分字段）+ 两个按钮：「保存并去对话」（主）、「只建项目」（次）。
2. **在对话里直接说**：3 条示例句 + 「回到对话」按钮。
3. **流程说明**：需求 → 语境 → 三档变体 → 质检 → 导出（一张 5 步图）。
4. **项目库**：卡片（分数、状态、变体、更新时间）+ 删除。

### 5.2 工作区

- TopBar 常驻「回到对话」；分数 chip 点进检查 tab。
- FlowStepper 显示当前阶段与下一步（如「下一步：补语境」/「下一步：跑质检」/「下一步：导出」），点击直达。
- 左栏「需求」tab：brief 五字段（内联编辑 + 保存）+ 「继续提需求」文本域（自动附带上下文：当前变体、选中元素选择器、未解决评论数、未修复问题数）+ 「复制给 Claude 并去对话」/「只保存到需求」。
- 其余 tab 与画布能力同 v1.1。

### 5.3 空态与首启

- 首次打开面板：引导卡（3 步：① 在对话里说要做什么 ② 面板看变体改画布 ③ 质检 ≥90 再导出），带「去对话」「写需求」按钮，可关闭且不再自动弹。
- 无项目：需求输入卡 + 示例。
- 无变体：提示「让 Claude 生成三档变体」+ 复制指令。
- 未选中元素：提示「按 E 选择模式，或从图层树选」。
- 桥未就绪：明确的「重新加载预览」。

## 六、需求动线设计（v1.2 核心）

面板内任何"要跟 Claude 说话"的地方，统一调用一个动作：

```
HandoffToClaude({ prompt })
  1. navigator.clipboard.writeText(prompt)
  2. ctx.layout.selectPanel(null)   // 回到 Conversation
  3. toast("需求已复制，在输入框 Ctrl+V 粘贴发送")
```

生成 prompt 的模板统一（可被 agent 直接执行）：

```
【设计台】项目 {name}（{id}），类型 {kind}
当前变体：{variant}；选中元素：{selector}；未解决评论：{n}；未修复问题：{m}
需求：{textarea}
请使用设计台工具链处理：必要时 design_context / design_system，改 design/{variant}.html，
然后 design_check 直到 ≥90，最后 design_export。
```

快捷入口（都复用 HandoffToClaude）：
- 总览「保存并去对话」
- 左栏「需求」tab 的「复制给 Claude 并去对话」
- 检查 tab「让 Claude 修复这些问题」（把 issues 序列化）
- 评论 tab「复制给 Claude」（把未解决评论序列化）
- 空态「让 Claude 生成变体/补语境」
- TopBar「回到对话」（只切面板，不复制）

## 七、快捷键（面板焦点内）

`⌘/Ctrl+S` 保存 · `⌘Z` 撤销 · `⇧⌘Z` 重做 · `⌘K` 命令面板 · `⌘\` 检查器 · `E` 选择 · `C` 评论 · `1/2/3` 变体 · `0` 适应 · `+/-` 缩放 · `⌘D` 复制元素 · `Delete` 删除 · `G` 网格 · `R` 标尺 · `?` 帮助 · `F6/⇧F6` 区域循环 · `Esc` 取消/返回。

## 八、与 Claude Design 的对照（流程层）

| Claude Design | 设计台 v1.2 |
|---|---|
| 对话 + artifact 面板并排（同一屏） | 对话为主界面，设计台是全局面板；面板内「需求」tab + HandoffToClaude 把需求带回对话（DSH 的对话与面板是互斥主区域，无法并排，这是框架差异） |
| 画板/图层/属性面板/F6/浮动工具条/评论 marker | v1.1 已实现 |

| 设计系统 artifact 分节 | 已实现（右栏设计系统） |
| 导出/交接/版本 | 已实现（导出 5 格式、版本快照） |
| "Send to Claude" 评论 | 评论 → agent 读取 + 「复制给 Claude」 |

## 九、v1.2 验收清单

1. 总览第一屏有需求输入区，提交后：创建项目 + brief、复制结构化 prompt、切回对话并 toast。
2. 工作区顶栏常驻「回到对话」；点击后回到 Conversation。
3. 左栏「需求」tab 可读写 brief（服务端持久化）；「继续提需求」自动带上下文，HandoffToClaude 可用。
4. FlowStepper 按项目状态高亮阶段并给出下一步动作。
5. 首启引导卡只出现一次（localStorage 记忆），可关闭。
6. 检查/评论 tab 的「复制给 Claude」生成可执行指令。
7. 新增路线 `POST /api/projects/:id/brief` 通过单元测试与活体 200。
8. 回归：v1.1 的图层/画布/属性/检查/导出/系统/版本功能不退化；单元测试全绿；活体截图（总览需求卡、工作区需求 tab、FlowStepper、回到对话）入 `_artifacts/design-studio/ui-v3/`。
